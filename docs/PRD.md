# 二手書交換平台系統 PRD 文件 (Product Requirements Document)

## 1. 專案概述
### 背景與動機
每到新學期，大學生都會面臨購買昂貴教科書的壓力，而許多已經修完課的學長姐手邊則有閒置的二手課本不知如何處理。為了解決教科書資源浪費及學生經濟負擔的問題，本專案致力於打造一個專屬校內的二手書交換平台系統，提供安全、便利的管道讓學生能夠輕鬆進行二手課本的買賣或交換。

### 目標用戶
- **大學生（一般使用者）**：需要尋找便宜的二手課本，或希望出售/交換自己不再使用的課本。
- **系學會 / 社團（組織用戶）**：可能需要代為統一收售二手書，或是舉辦二手書展、傳承活動的單位。

### 核心價值主張
- **降低學生的學習成本**：透過二手書流通，讓學生能以實惠的價格取得教材。
- **活化閒置資源**：將不再需要的課本轉移給需要的人，實現資源循環利用。
- **校園專屬、安全可靠**：以校園為單位，減少跨校面交的風險與物流成本。

## 2. 功能需求

### 主要功能與使用者故事

#### 功能一：書籍上架系統
- **作為** 一名想要賣書的大學生，**我希望** 能夠輕鬆地上傳二手書的資訊（書名、作者、課程名稱、書況照片、售價/交換條件），**以便** 其他同學可以快速瀏覽並購買。
- **作為** 一個系學會，**我希望** 能夠批次上架收集來的二手書，**以便** 高效管理並幫助學弟妹。

#### 功能二：分類檢索功能
- **作為** 一名尋找特定課本的學生，**我希望** 能夠透過書名、作者、課程名稱、科系分類或 ISBN 進行搜尋與篩選，**以便** 快速找到我所需要的課本。

#### 功能三：預約請求系統
- **作為** 一名買家，**我希望** 對感興趣的二手書發出預約或購買請求，**以便** 鎖定該書籍並與賣家確認交易意願。
- **作為** 一名賣家，**我希望** 能收到買家的預約通知並選擇接受或拒絕，**以便** 妥善管理我的書籍銷售狀態。

#### 功能四：個人書櫃管理
- **作為** 一名平台用戶，**我希望** 有一個個人書櫃頁面，可以查看我目前上架的書籍、已售出的書籍以及我正在預約/追蹤的書籍，**以便** 追蹤我的交易紀錄與進度。

#### 功能五：即時留言 / 私訊系統
- **作為** 一名買家/賣家，**我希望** 能夠透過系統與對方進行即時留言或私訊，**以便** 討論書籍細節、議價或是約定校內面交的時間與地點。

## 3. 非功能需求

### 技術限制
- **後端框架**：使用 Flask (Python) 開發。
- **前端模板**：使用 Jinja2 結合 HTML/CSS/JavaScript。
- **資料庫**：使用 SQLite 儲存使用者資料、書籍資訊、交易紀錄與留言內容。

### 效能與安全考量
- **響應時間**：頁面載入時間應小於 2 秒，確保良好的使用者體驗。
- **使用者驗證**：實作登入與註冊機制（密碼須經過 Hash 加密儲存，例如使用 Werkzeug），確保帳號安全。
- **權限控管**：確保用戶只能修改或刪除自己上架的書籍與個人資料。
- **防範攻擊**：防範常見的網頁攻擊，如 SQL Injection（透過 ORM 或 Parameterized queries 防範）與 XSS（透過 Jinja2 自動轉義防範）。

## 4. MVP (Minimum Viable Product) 範圍

### Must Have (必須擁有)
- 使用者註冊與登入（基本身分驗證）。
- 書籍上架系統（新增、修改、刪除書籍資訊）。
- 基本分類與搜尋功能（依書名、科系關鍵字搜尋）。
- 個人書櫃管理（查看自己的上架清單與狀態）。
- 基本留言板功能（在書籍頁面下方公開留言詢問）。

### Should Have (應該擁有)
- 預約請求系統（買家點擊預約，賣家確認）。
- 即時私訊系統（買賣雙方一對一私人對話，取代公開留言）。
- 書籍狀態追蹤（上架中、已被預約、已售出）。

### Nice to Have (最好擁有)
- 系學會/社團專屬帳號標章與批次管理功能。
- 評價與信用機制（交易完成後互相給予評分）。
- 校內面交地圖或地點建議功能。
- 電子郵件/系統通知提醒。
